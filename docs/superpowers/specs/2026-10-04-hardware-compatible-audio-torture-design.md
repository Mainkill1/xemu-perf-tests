# Hardware-compatible audio torture suite design

## Outcome and scope

PR #55 will deliver executable, individually selectable coverage for all 138
cases generated by `utils/audio_torture_cases.py`. The resulting XISO must use
Xbox guest-visible facilities and remain runnable on an original Xbox. A
Steam Deck running xemu is the available native test host; there is no original
Xbox in this campaign. Passing xemu results therefore establish emulator
regression evidence, not original-hardware qualification.

The 138 IDs and parameters remain defined by the existing matrix. No case may
be counted as implemented merely because its input was generated, a voice was
requested, or a timer elapsed. The existing `McpxVoiceTests` remain separate
xemu-only diagnostic evidence; their hard-coded experimental mode is not a
hardware-safety precedent for this suite.

## Current gap and reference lessons

| Current PR state | Required end state |
| --- | --- |
| 138 planned descriptors, no `audio.*` executable catalog leaves | 138 generated, selectable leaves with case-specific observations |
| Optional one-voice S16 bootstrap | Two owned backends covering their declared case families |
| Reference wrapper infers completed frames from input length or a delay | Completion reported only from observed device progress or an explicit expected refusal |
| AC'97 path blocked on teardown | Test-owned AC'97 lifecycle with proved DMA quiescence and restoration |

NXDK's public helper is a narrow AC'97 output API; the pinned `nxdk-audio`
project describes broader MCPX behavior but its present wrapper implements
only a subset of this matrix. xemu register definitions are useful for
candidate hardware contracts, but emulator behavior alone does not establish
what original hardware will do. The design therefore uses independently
worded guest-visible behavior and observable acceptance checks, not copied
reference implementation structure.

## Architecture

The case generator produces one immutable guest descriptor per planned ID:
backend, format, voice count, source layout, control sequence, intended paths,
expected boundary outcome, and oracle profile. Build-time generation ensures
the guest descriptor table, catalog, and selected plans use the same IDs and
parameters. A host contract test compares the generated descriptors with all
138 matrix entries, including the zero-voice control and 257-allocation denial.

The guest runner owns a bounded device session for each selected case. It
checks whether the device is available, records relevant pre-test state,
allocates guarded DMA memory, submits the fixed workload, observes completion,
checks output or device state against the case oracle, quiesces DMA and voices,
restores state, and records the post-test state. A case must not free a possible
DMA target when quiescence is unproved. Cleanup failure is a failed case and
prevents later audio cases from running in the same process.

Two independent backend owners sit behind this common lifecycle:

- `mcpx_apu_raw` resolves the APU through guest-visible PCI and BAR0, then
  controls VP, SGE/SSL, mixbins, GP, EP, and their DMA using documented or
  independently validated guest-visible state. It does not assume a fixed
  xemu host address, an emulator-private command, or an xemu-only completion
  counter. The existing `nxdk-audio` path may serve as a comparison for a
  subset, but it cannot substitute for raw 256-slot and control-path cases.
- `ac97_dma` owns the output descriptors, interrupt/progress observation, and
  restoration needed by its ten S16-stereo cases. It does not call NXDK's
  public `XAudio` helper, which lacks public deinitialization. The AC'97
  backend never claims VP, GP, EP, format, or HRTF coverage.

Case support is promoted incrementally on the same PR branch: first safe
ownership and one S16 control, then formats/rates, scaling and memory
boundaries, stream/mode/control paths, filter/HRTF/mixbin and GP/EP paths,
AC'97, and finally the combined ceiling case. Promotion adds an executable
catalog leaf only when its workload, oracle, timeout, and teardown evidence
exist. PR #55 stays draft until every one of the 138 leaves is promoted and
validated.

## Workload and oracle contract

Every input is deterministic and redistributable. Existing checked-in audio
fixtures retain their exact manifest hashes; generated signals use fixed
integer state. Setup and fixture loading occur outside the measured body.
Performance runs do not write audio files inside timed work.

Each result records: case ID and descriptor revision; source checksum;
requested and accepted resource counts; submitted work; a device-observed
completion or expected refusal; the oracle name, observed values and verdict;
elapsed work interval if eligible; and pre/post ownership and cleanup verdicts.
No inferred `completed_frames` field may be presented as an observed count.

Oracle strength follows the path being claimed:

| Cases | Required portable evidence |
| --- | --- |
| 0 voices and 257 allocation request | Exact accepted/refused count, unchanged output state, and clean ownership release. These are correctness-only. |
| VP format, rate, pitch, scale, buffer and locality | Actual VP progress plus guest-readable mixed output checked against deterministic integer or tolerance-based expectations; source checksum alone is insufficient. |
| Streaming, modes, control and churn | Observed state transitions, bounded completion and output continuity/discontinuity appropriate to the selected sequence. |
| Mixbin, filter, HRTF, GP and EP | Configured path state plus output that changes as the feature is enabled or routed; a setup register write alone is insufficient path proof. |
| AC'97 refill and locality | Descriptor ownership/consumption, interrupt or status progress, explicit drain/underrun result, and no outstanding DMA at teardown. This proves the DMA path, not analog fidelity. |
| Combined ceiling | All constituent path checks, guarded memory, bounded completion and clean teardown; a single aggregate timer is not its oracle. |

If a claimed audio output is not observable through a portable guest-readable
point, an independently captured output artifact may supplement the result.
Without either a portable output observation or such an artifact, an
output-dependent case remains unqualified; it must not receive a fabricated
PASS or performance label. Emulator-only path counters are optional diagnostic
evidence and cannot be required for the XISO to run on Xbox hardware.

The pinned upstream xemu build is a regression reference, not a physical-
hardware oracle. Its exact executable digest and source revision are recorded
with the XISO digest and case manifest. A difference between baseline and
candidate is retained as a failure requiring attribution; agreement does not
prove real-hardware correctness.

## Failure and isolation policy

Each case has a finite timeout and an explicit failure record for unavailable
hardware, unsafe pre-existing ownership, unsupported format/control state,
allocation failure outside a declared denial probe, missing progress, oracle
mismatch, guard corruption, or failed teardown. An expected denial passes only
if no work was submitted and the device state remained safe. Fatal assertions
must not bypass result emission for ordinary case failures.

The opt-in audio plan groups cases by backend and lifecycle requirements.
AC'97 and raw MCPX ownership never overlap. If a case cannot establish safe
in-process restoration, it remains unregistered until an Xbox-compatible
fresh-title/reboot isolation route is implemented and tested; ordering audio
last does not satisfy restoration. A failure that leaves DMA ownership
uncertain stops subsequent cases rather than risking memory reuse.

## Verification and release gate

The host gate checks all 138 descriptors and oracle profiles, fixture
regeneration, input/reference algorithms, boundary denials, failure records,
catalog/plan generation, and a normal plus audio-enabled Release XISO build.
Native validation uses the Deck's test runner: one complete upstream-baseline
campaign and one complete candidate campaign with the same XISO, settings and
selected 138 IDs. Preserve exact run receipts, guest results, executable/ISO
hashes, failures, and any output artifacts. Repeat only individual failures or
ambiguous cases as needed for diagnosis; do not infer success from a launch or
partial plan.

PR #55 may leave draft only when all 138 selected IDs produce complete records,
the declared oracles and teardown checks pass, and the baseline/candidate
comparison has no unattributed failure. Performance claims additionally
require a qualified path observation and a separately valid timing comparison;
this PR's correctness gate does not itself grant that claim. Because no Xbox
is available, the final report must explicitly state that original-hardware
execution and analog-output fidelity were not verified.

## Implementation partitions on the same PR

1. Common descriptor/result contract and hardware-safe ownership, proven by
   one raw S16 case and a failing cleanup test.
2. Raw VP formats, source rates, pitch, scale, allocation boundaries, buffer
   crossings and memory locality.
3. Streaming, mode/control, churn, mixbin, filter, 3D/HRTF, GP and EP cases.
4. Test-owned AC'97 descriptor/refill/locality backend and its ten cases.
5. Combined ceiling case, generated catalog/plans, full host/build gates, and
   the two native runner campaigns.

Each partition must be independently testable before the next is promoted.
They are not separate completion claims: all five belong to PR #55.

## Source and provenance boundary

The target suite is Unlicense. Design research used the public [xemu APU
register reference](https://github.com/xemu-project/xemu/blob/master/hw/xbox/mcpx/apu/apu_regs.h)
(QEMU/xemu GPL-family source), [NXDK AC'97 API](https://github.com/abaire/nxdk/blob/master/lib/hal/audio.h)
(MIT-marked header), and the [nxdk-audio feature documentation](https://github.com/Ryzee119/nxdk-audio)
(the pinned backend files carry MIT notices). These sources identify candidate
capabilities and constraints, not a hardware certification. No third-party
implementation expression is to be copied into this repo; compatibility-
necessary device constants and API names must be attributed and validated.

Rejected alternatives: registering the 138 planned IDs without actual device
work; treating NXDK `XAudio` as a VP backend; treating the current reference
wrapper's inferred frame count as completion proof; or relying on xemu-only
instrumentation for an Xbox-compatible PASS.
