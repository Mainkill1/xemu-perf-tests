# MCPX Voice Fixture Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan inline. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retain guest tests that observe real MCPX nonstreaming ADPCM and a PCM control.

**Architecture:** Separate deterministic payload generation from the guest MMIO driver. The driver observes voice progress and two GP mix bins, reports narrow output assertions, and restores inactive state after an explicit quiescence sequence.

**Tech Stack:** C++17, pinned NXDK, existing TestSuite/catalog, Python host contracts.

**Spec:** `docs/mcpx-adpcm-voices.md`

## Global constraints

- Five generated-input leaves, no retail assets or copied external driver/decoder source.
- Experimental xemu-only support; full DSP required; no hardware running-mode claim.
- Guest wait latency is NOT COMPARABLE as throughput; no speedup from pacing.
- Native testing uses maintained HTTP on Steam Deck 10.0.0.123.
- Test changes get a separate draft PR; emulator evidence stays with xemu.

## Review focus

- A page-crossing block must not read the intervening physical poison page.
- Silent output must fail, even when CBO advances.
- Stereo output must preserve sign/channel identity.
- A timeout must unlink lists and fence before releasing DMA memory.
- An already running engine must be refused without changing its state.
