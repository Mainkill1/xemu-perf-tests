# MCPX Voice Fixture Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan inline. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retain guest tests that observe real MCPX nonstreaming ADPCM and a PCM control.

**Architecture:** Separate deterministic payload generation from the guest MMIO driver. The driver observes voice progress and two GP mix bins, reports narrow output assertions, and restores inactive state after an explicit quiescence sequence.

**Tech Stack:** C++17, pinned NXDK, existing TestSuite/catalog, Python host contracts.

**Spec:** `docs/mcpx-adpcm-voices.md`

## Global constraints

- Five generated-input leaves, no retail assets or copied external driver/decoder source.
- Experimental xemu-only support; full DSP required; no hardware running-mode claim.
- Guest wait latency is NOT COMPARABLE as throughput; no speedup from pacing.
- Native testing uses maintained HTTP on Steam Deck 10.0.0.123.
- Test changes get a separate draft PR; emulator evidence stays with xemu.

## Review focus

- A page-crossing block must not read the intervening physical poison page.
- Silent output must fail, even when CBO advances.
- Stereo output must preserve sign/channel identity.
- A timeout must unlink lists and fence before releasing DMA memory.
- An already running engine must be refused without changing its state.

## Execution record

Recipe contracts: RED missing header (compiler failure), then three focused checks GREEN; baseline was 140 checks, recipe suite 143 checks passed. Task 2 registration was RED with five missing routes, then GREEN after implementation; the expanded host suite is 144 passing checks. Catalog generation changes 159 parent leaves to 164 leaves; groups remain five. No native fixture coverage is claimed.

Ruling: require inactive/unconfigured state and retain empty list tops after cleanup, rather than restoring arbitrary prior lists. A frame waiting inside the throttle can run once after SECTL disable; restoring old list pointers before it runs could revive DMA. This costs compatibility with applications that already configured the APU; the experimental fixture reports refusal instead of taking over their state. Failed stop verification retains allocations until process reset.

The first Release XISO builds successfully with pinned NXDK and all 144 contracts pass. The new MCPX source emits no compiler warnings; unchanged workload sources and the existing linker emit retained warnings. Native gates remain incomplete.

Independent whole-branch review at `8294b8a` found one Important coverage gap:
checking only the later mix window could miss corruption of the first crossing
block. A single fix pass makes crossing leaves replay that 64-sample block,
clears the prior mix before arming, and uses engine XGSCNT progress because
the short-loop voice offset can alias between polls. The compiled LoopSamples
contract was RED (missing implementation), then GREEN after the fix; the
scattered first-block contract also proves a contiguous read encounters poison.
Review also found that setup failure skipped per-leaf output. Refusal/allocation/
copy failures now emit FAIL metadata, zero measured samples and TEST_END through
the normal result writer. No new native result is claimed by this fix.

The broader discovery command also exposed a packaging gap: the strict runner

Existing runner versions may expose this newly added suite under `other`;
select the five exact IDs instead of assuming an audio category in the runner.

The native setup refusal prompted a read-only boot-state audit. The revised
ownership contract accepts a stopped engine with disabled DSPs and empty
lists even when old BIOS table addresses remain, saves/restores those addresses
and the GP reset word, and still rejects enabled processors or linked voices.
This supersedes the initial zero-table-only ownership ruling above. Compiled
ownership contracts were RED with the missing predicate before implementation.
Raw native audits and original failures belong to the owning xemu PR.

The first native pipeline observation was RED against the declared unity mix
oracle while engine progress and cleanup passed. The fixture now explicitly
programs zero submix headroom for its two observed bins; boot gain state must
not determine the generated-input contract. This setting belongs to the
fixture's idle mix configuration and remains zero afterward, rather than
pretending to restore an unreadable prior headroom value. Original raw failures
remain in xemu evidence; the expected mathematical oracle is unchanged.
